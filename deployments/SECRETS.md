# Lahijan — Secrets Management

This document lists every secret an operator manages for a Lahijan
production deploy, where it lives, and how to rotate it. **The backup
script does NOT dump any of these** — losing them is unrecoverable
without a key-rotation procedure.

## 1. Secret inventory

| Secret | Env var | Where it's used | Generated by |
|--------|---------|-----------------|--------------|
| Postgres superuser password | `POSTGRES_SUPERUSER_PASSWORD` | Postgres container entrypoint | `openssl rand -base64 32` |
| Lahijan DB password | `LAHIJAN_DATABASE_PASSWORD` | Lahijan pool, `pg_dump` | `openssl rand -base64 32` |
| PowerDNS DB password | `PDNS_DATABASE_PASSWORD` | PDNS daemon | `openssl rand -base64 32` |
| SeaweedFS DB password | `SEAWEED_DATABASE_PASSWORD` | SeaweedFS Filer | `openssl rand -base64 32` |
| PowerDNS API key | `PDNS_API_KEY` | Sent by Lahijan, expected by PDNS | `openssl rand -hex 32` |
| SeaweedFS admin access key | `SEAWEEDFS_S3_ACCESS_KEY` | Sent by Lahijan, expected by weed s3 | `openssl rand -hex 16` |
| SeaweedFS admin secret key | `SEAWEEDFS_S3_SECRET_KEY` | Sent by Lahijan, expected by weed s3 | `openssl rand -hex 32` |
| Auth HMAC signing key | `LAHIJAN_AUTH_SIGNING_KEY` | Cookies, email tokens | `openssl rand -base64 48` |
| Auth AES-256-GCM encryption key | `LAHIJAN_AUTH_SECRETS_ENCRYPTIONKEY` | IdP tokens, MFA secrets at rest | `openssl rand -base64 32` |
| SMTP password | `LAHIJAN_SMTP_PASSWORD` | Outbound auth emails | Your SMTP provider |
| Bootstrap admin password (optional) | `LAHIJAN_BOOTSTRAP_ADMIN_PASSWORD` | First-run admin | Operator OR random (logged once) |
| Grafana admin password | `GRAFANA_ADMIN_PASSWORD` | Grafana web UI | Operator-chosen |
| Grafana basic-auth hash | `GRAFANA_BASIC_AUTH_HASH` | Caddyfile basic_auth | `caddy hash-password` |
| Jaeger basic-auth hash | `JAEGER_BASIC_AUTH_HASH` | Caddyfile basic_auth | `caddy hash-password` |

## 2. Where secrets live

In a Lahijan deploy, every secret is sourced from
`deployments/.env.prod`. The file is **gitignored** — never commit it.

For higher-security deploys, source the values from:

- **Docker secrets** (Compose v3.1+): mount each secret as a file under
  `/run/secrets/<name>` and use Lahijan's `*_FILE` env vars (e.g.
  `LAHIJAN_AUTH_SIGNING_KEY_FILE=/run/secrets/auth_signing_key`).
- **HashiCorp Vault** via `vault agent` templating into the env file.
- **Cloud secret managers** (AWS Secrets Manager, GCP Secret Manager)
  via a sidecar that fetches + renders the env file before Lahijan
  boots.

The Lahijan binary itself reads secrets from env vars (or `*_FILE`
variants where supported) once at startup and never re-reads them.

## 3. Key rotation procedures

### 3.1 Auth HMAC signing key

**Impact:** rotating this invalidates every existing session cookie +
refresh token. Every user must log in again.

**Procedure:**

1. Pick a new value: `NEW=$(openssl rand -base64 48)`.
2. In `.env.prod`:
   ```
   LAHIJAN_AUTH_SIGNING_KEY=$NEW
   ```
3. Restart Lahijan:
   ```
   docker compose --env-file deployments/.env.prod -f deployments/docker-compose.prod.yml up -d --force-recreate lahijan
   ```
4. Notify users (they will see a "session expired" prompt on next
   action).

### 3.2 Auth AES-256-GCM encryption key

**Impact:** rotating this **invalidates every external IdP token**
(OAuth / OIDC refresh tokens) + every TOTP secret at rest. Users must
re-link IdPs + re-enroll TOTP. This is a major event.

The encryption key is the AES-256-GCM master key for `auth.secrets.encryptionKey`.
Per ADR-0004 we use AES-GCM column-level encryption for MVP; the rotation
path is documented here but the Lahijan binary does NOT yet ship a
rotation command (it's a Phase 7 deliverable).

**Procedure (manual, for now):**

1. Take a fresh backup.
2. Decrypt every encrypted column via a maintenance script (TBD —
   follow https://github.com/avestura/lahijan/issues for status).
3. Set the new key in `.env.prod`.
4. Re-encrypt every column.
5. Restart Lahijan.

**Until the rotation command ships, the recommendation is:**
generate this key ONCE at install time, store it in a long-lived
secret manager (Vault, AWS Secrets Manager, or a printed-out paper
backup), and never rotate it. Losing it locks every encrypted column.

### 3.3 Postgres / Lahijan / PDNS / SeaweedFS DB passwords

**Procedure (Lahijan DB; mirror for the others):**

1. Generate a new value: `NEW=$(openssl rand -base64 32)`.
2. Connect to Postgres as superuser + alter the role:
   ```
   docker exec -it lahijan-prod-postgres psql -U postgres -d postgres -c \
     "ALTER ROLE lahijan PASSWORD '$NEW';"
   ```
3. Update `.env.prod`:
   ```
   LAHIJAN_DATABASE_PASSWORD=$NEW
   ```
4. Restart Lahijan + the matching service so the new password is picked
   up by the pool:
   ```
   docker compose ... up -d --force-recreate lahijan powerdns seaweed-filer
   ```

### 3.4 PowerDNS API key

1. Generate new value: `NEW=$(openssl rand -hex 32)`.
2. Update `.env.prod`:
   ```
   PDNS_API_KEY=$NEW
   ```
   (This value is shared: it's what PDNS expects AND what Lahijan sends.
   The same env var populates both sides of the compose.)
3. Restart both services:
   ```
   docker compose ... up -d --force-recreate powerdns lahijan
   ```

### 3.5 SeaweedFS admin credentials

1. Generate new values:
   ```
   AK=$(openssl rand -hex 16)
   SK=$(openssl rand -hex 32)
   ```
2. **Before** restarting, write the new credentials into the SeaweedFS
   s3.json. The compose mounts the file read-only, so:
   ```
   cat > deployments/seaweedfs/s3.json <<EOF
   {
     "identities": [
       {
         "name": "lahijan_admin",
         "credentials": { "access_key": "$AK", "secret_key": "$SK" },
         "actions": ["Admin", "Read", "Write", "List", "Tagging"],
         "is_admin": true
       }
     ]
   }
   EOF
   ```
3. Update `.env.prod`:
   ```
   SEAWEEDFS_S3_ACCESS_KEY=$AK
   SEAWEEDFS_S3_SECRET_KEY=$SK
   ```
4. Restart SeaweedFS + Lahijan:
   ```
   docker compose ... up -d --force-recreate seaweed-s3 lahijan
   ```

Existing per-user IAM credentials Lahijan minted are NOT affected —
they're stored in the SeaweedFS Filer (Postgres), not in s3.json.

### 3.6 First-run admin password

The bootstrap admin password is rotated via the dashboard, not via env
vars. After first login:

1. Open `https://<host>/profile/security`.
2. Click "Change password" and follow the prompt.

If you forgot the original password (and lost the one-time log line),
reset via the database directly:

```
docker exec lahijan-prod-postgres psql -U lahijan -d lahijan -c \
  "UPDATE users SET password_hash = NULL WHERE email = 'admin@example.com';"
```

This forces a password-reset flow on next login (Lahijan will email the
reset link if SMTP is configured).

## 4. Audit log

Every privileged action emits an audit event (ADR-0019). The audit log
is append-only — even an admin cannot delete rows. Operators should
browse `https://<host>/audit` to monitor for unusual activity
(privilege grants, mass deletions, suspicious logins).

## 5. Backup considerations

- **The backup script does NOT include any secret.** A backup tarball
  alone cannot rebuild a working deploy — the auth signing + encryption
  keys must also be preserved.
- **Store the env file + the backup tarball in separate locations.**
  Compromising one should not compromise the other.
- **Test the restore + key-rotation procedures on a fresh VM at least
  once before relying on them for production.**
